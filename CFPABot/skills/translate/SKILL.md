# 译中

审查流程不走本 skill，正文暂作占位：校对确认的译法经验记在这里，需要补译、新译时再按下面走。复用译前的 `terms.tsv`、`STYLE.md`、`format.md`；没有就先跑 `skill://prep`。审查用的定译以 `pr://<n>/terms` 的冻结表为准，`terms.tsv` 只是工作副本。

译文合并在 `local://` 完成，产物由人取走落到仓库。

## 切块

- 按原文 token 切，8,000–10,000 一片；条目长度能差一千倍，不按条数切。
- 一个单元一次 `write` 写得完。
- 同一场景、同一角色、同一文本类型（UI、对话、任务、道具）同片，不按 id 顺序横切。
- 同一原文的多个站点放同一组。

## 派单

每个单元一份 `local://units/unit-NN.json`（id + 原文），交付 `local://out/unit-NN.json`（只含 id → 译文）。

固定段必须逐字节相同，才能命中前缀缓存：

- 格式硬规则：占位符、格式码、标签、换行、引号。
- 本批命中的 `bucket=lock` 词，一条不漏。
- 三条风格样本。
- 交付格式和自检命令。

变化段只放本单元条目和上下文。碎片给四样：原文 / 现值 / id / 接续（`+` 顺序拼接，`/` 互斥分支）。

## 执行

| 方式 | 适合 | 注意 |
|---|---|---|
| 主代理自己写 | 小批、需要反复查上下文 | 直接写 `local://out/` |
| `eval` 跑脚本 | 机械整理、校验、拆壳 | 在 `local://` 内读写；bash 未开启时这是唯一选择 |

`delegate` 只用于审查分片（agent 用 review），不拿来翻译。

首译不要用互不相干的多次单条调用：块与块之间没有共享裁定，术语和语气会漂。一次派一个单元，固定段保持一致。

## 合并

合并只由主代理做。

1. 键集：交付的键必须都在本单元里；少交的留在队列，多交的报错。
2. 格式：占位符、标签、换行、制表符与原文一致。
3. 拆壳：模型可能按「文件名 → JSON 文本」回答，递归拆掉外层，直给键优先。
4. 归一：原文没有字面 `\n` 时，把值里的字面 `\n` 反转义。
5. 丢弃：格式不合、长句原文抄回、键名越界的一律丢，不猜。
6. 覆盖：人工裁定最后套用，优先级最高。

单元产物不改 `terms.tsv`。新词、多译、冲突写进 `reports/unit-NN.md`；父代理每批收齐后裁决：改定译就 `write pr://<n>/terms` 更新冻结表，其余覆盖 `terms.tsv`/`STYLE.md`/`format.md`，下一批带上新值。
